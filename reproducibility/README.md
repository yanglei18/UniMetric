# Reproducing Metric-Depth experiments

The published matrix has 12 datasets × 9 depth models plus one default YAML
per dataset (120 production YAMLs). Algorithmic YAML values are preserved;
resource paths use the repository-relative defaults documented below. The
relative source/config hashes in `source-and-config-manifest.json` identify the
public project files. `freeze_manifest.py --include-vendor` can separately
record a local ignored vendor cache for an exact-machine audit.

## 1. Environment and third-party code

Run `bash scripts/install_gfm.sh` from the repository root to install all
nine backends, SAM 2, and their checkpoints across the two environments, then
run `conda activate unimetric` for the default LingBot-Map/nuScenes run.
No model or environment selection is needed during installation. Eight models
share `unimetric` (PyTorch 2.6.0, torchvision
0.21.0, cu124, NumPy 1.26.4). DVLT alone uses `unimetric-dvlt` (PyTorch
2.5.1, cu124, NumPy 2 and its other dependency overrides). Optional explicit
model selection, including `common` and `all`, is documented in the
[GFM environment guide](../docs/gfm-environments.md#optional-model-selection).
VGGT-Omega checkpoint access requires approval from its Hugging Face publisher
and authentication; supply `HF_TOKEN` before installation. The installer
cannot grant gated access. Rerun the same command after obtaining access.
Adding a shared model reuses the environment and resolves and checks the
requirements of previously recorded models together with the new selection.

The installer uses Python 3.11 and records requirements, source revisions,
installation status, and `pip freeze` under the Git-ignored
`reproducibility/environments/<env-name>/` directory. Its checks cover imports,
array interoperability and CUDA availability, not full benchmark reproduction.
Do not install the unmodified `requirements-base.txt` into the DVLT environment
afterward. The old-server
package snapshot is in `env/QWen-pip-versions.txt` and
`env/QWen-conda-explicit.txt`; it is a reference, not a portable one-command
environment installer. The two groups follow the server's QWen/dvlt
organization and core torch/NumPy versions, but do not reproduce its complete
environments: the server's DVLT environment uses Python 3.12, while this
installer uses Python 3.11 for both groups. Source and weight versions are pinned in
`../scripts/gfm_profiles.json`; these are installation revisions, not a claim
that all historical experiments used these exact upstream commits.
The local development-server `vendor/` cache is ignored by Git; see
[`../vendor/README.md`](../vendor/README.md) for links and licensing notes.

## 2. Paths, inputs, and API credentials

Datasets and weights are obtained separately. Place them in the default
directories below and run the supplied YAMLs from the repository root without editing them:

| Resource | Default location under the repository root |
| --- | --- |
| Dataset frames, calibration and evaluation ground truth | `data/metric_bench/<dataset>/`; the default run uses `data/metric_bench/nuScenes/` from `autonomous_driving.zip` |
| Model source and weights | `vendor/` and `pretrained_model/`; see the [asset layout](../vendor/README.md#default-directories) |
| SAM2 checkpoint | `checkpoints/sam2.1_hiera_large.pt`; configuration is resolved inside the installed SAM2 package |
| Temporary inference files | `tmp/` |
| Results and prepared images | `outputs/<dataset>/` and `p3_images/<dataset>/<sequence>/` |
| Bundled VLM responses | `precomputed/vlm_results_12datasets.zip`; selected dataset/sequences are automatically restored to `outputs/<dataset>/<sequence>/vlm_outputs/results/` without overwriting existing files |

The machine-local `external-assets-manifest.json` is generated by
`freeze_external_assets.py` and excluded from the public Git index because it
contains absolute server paths. It records hashes for directly named model
files. One verified reference is `lingbot-map-long.pt` with SHA-256
`832bc82cbae0bc9bbe946ef5ee1f7226abd8c0e183ccf8beddbb3d133576f409`.

Frames covered by the bundled VLM responses need no API credentials. New VLM requests use `DOUBAO_API_KEY` and `DOUBAO_BASE_URL` for the default Doubao configuration. Humanoid Everyday's Qwen API configs need `MODEL_KEY` and `BASE_URL` (optionally `MODEL_NAME`). Never store key values in a YAML, log, or Git commit.

## 3. Validate and run

```bash
python reproducibility/check_setup.py
python reproducibility/test_active_features.py
python reproducibility/test_prompts.py
python reproducibility/test_supported_models.py
python -m pytest -q tests/test_omega_balanced_preprocess.py tests/test_omega_dataset_intrinsics.py
```

After preparing the default resources, run LingBot-Map on
nuScenes without arguments. This uses `configs/nuscenes/lingbot_map_long.yaml`
with its existing algorithm settings and frame-selection protocol:

```bash
conda activate unimetric
python get_metric_scale.py
```

The normal pipeline restores and reuses VLM responses, creates SAM masks, prepares P3 images,
predicts depth, estimates scale and saves metrics. `depth_only: true` requires
existing VLM JSON and intentionally skips scale/metrics.
`cleanup_depth_outputs_after_metrics: true` removes the current model's depth
intermediates after metrics, not VLM/SAM caches. `runtime.reuse_vlm_results` is enabled by default, independently of full pipeline reuse. Missing VLM responses are generated using the configured service. Set `runtime.resume_existing_results: true` only if code, YAML, dataset and cache provenance are identical. To regenerate cached VLM responses, disable both reuse flags.

## 4. Preserved behavior and limitations

- VGGT-Omega retains `balanced` preprocessing and dataset intrinsics for 3EED.
- JRDB per-sequence anchor overrides are applied at the scale stage.
- Argoverse's explicit prompt forwards the historical `default.py` driving
  prompts; four task texts are tested for exact equality.
- CEAR/Humanoid Scal3R offload, FusionPortable plane-mask fallback, V2X Radar
  camera-translation/dynamic-anchor options, and Humanoid Qwen/hard-sequence
  behavior are retained.

On the original validation host, all 120 YAMLs parsed, 18 overrides and 281
configured prompt routes passed checks, and six Omega tests passed. Full GPU
metrics were **not** re-run: PyTorch could not initialize CUDA there, and the
validation shell had no VLM API credentials. API responses may also vary over
time; static checks alone do not prove identical final metrics. Licensing of
first-party code is pending rights-holder confirmation; see
[`../LICENSING.md`](../LICENSING.md).
